# V0.9 local validation — application dashboard

Validated locally on 2026-09-30 using Windows PowerShell, Ubuntu WSL, Docker Engine/Compose, Java 25, Node.js 24.21.0, and Chrome. This report records local evidence only; it does not claim a hosted workflow run, image publication, release, commit, or push.

## Scope and decisions

- Added a separate React/TypeScript/Vite application in `dashboard/`; Grafana remains the platform telemetry UI.
- The browser uses relative `/api` requests. Vite proxies development traffic and unprivileged NGINX proxies container traffic to `backend:8080`, so no browser credentials or new CORS policy are required.
- The UI is read-only and consumes existing service, reliability, timeline, health-check, deployment, deployment-metrics, incident, current-incident, and incident-metrics DTOs. No backend feature or incident algorithm was added.
- Overview requests use a four-request concurrency limit. Detail sections fail independently. Requests have a 10-second timeout, and bounded 10-second polling waits until the previous cycle completes, pauses while the page is hidden, and aborts during unmount.
- The latency/status chart is an accessible SVG generated from real timeline data and downsamples large histories while retaining failures and latency peaks. No charting framework was added.
- A small backend correction uses a bulk repository delete so PostgreSQL can apply the existing cascades when a monitored service has a current deployment. The previous entity delete could raise `TransientPropertyValueException`; a real PostgreSQL regression test covers service, deployment, and health-check removal.
- All Maven and application image versions are `0.9.0-SNAPSHOT`. Existing Flyway migrations V1–V5 and stored monitoring history are unchanged.

## Limitations and deferred work

- Trusted local environments only: no application authentication, authorization, TLS termination, or tenant isolation.
- The dashboard is read-only and uses polling, not WebSockets or SSE.
- Overview reliability requires one existing metrics request per service, bounded to four concurrent requests; this is not a large-fleet performance benchmark.
- The timeline is client-rendered and downsampled for display; PostgreSQL remains the authoritative history.
- Grafana remains responsible for JVM, Kafka, tracing, and infrastructure telemetry.
- Alerts, external notifications, automatic rollback, cloud/Kubernetes deployment, and V1.0 security work remain deferred.
- Hosted Actions must independently validate the uncommitted V0.9 tree after review and push.
