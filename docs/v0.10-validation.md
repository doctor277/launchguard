# V0.10 local validation — AWS cloud deployment

Validated locally on 2026-10-01 using Windows PowerShell, Ubuntu WSL, Docker Engine/Compose, Java 25, Node.js 24.21.0, Terraform 1.14.6, AWS provider 6.67.0, TFLint 0.64.0, and Playwright Chromium 153. No AWS credentials were used, no Terraform plan/apply/destroy was run, and no cloud resources, images, commits, or pushes were created.

## Scope and decisions

- Added modular Terraform for VPC/subnets/routing/security groups, six immutable ECR repositories, ECS Fargate, ALB routing, RDS PostgreSQL, optional MSK Serverless, CloudWatch logs, private service discovery, Secrets Manager references, and optional GitHub OIDC delivery IAM.
- Selected MSK Serverless as the managed Kafka architecture because it preserves LaunchGuard's Kafka event contracts with less operational burden than provisioned or self-hosted brokers. It is disabled by default because continuous cluster-hour cost is unsuitable for an idle portfolio environment.
- All ECS desired counts, ALB ingress, MSK, NAT, VPC endpoints, and GitHub OIDC are disabled by default. A required billing acknowledgement and blocking Terraform resource preconditions prevent an accidental billable baseline, private tasks without egress, Internet-dependent tasks without NAT, and backend/worker tasks without Kafka connectivity.
- Added an opt-in `aws` Spring profile for MSK IAM/TLS. Local Compose retains PLAINTEXT Kafka and replication factor 1; the AWS task definitions set replication factor 3.
- Added a manual-only, protected-environment AWS workflow. It reuses full CI, authenticates with OIDC, publishes six immutable commit-SHA images, registers task-definition revisions, updates services, waits for stability, and optionally reports the deployment.
- Bumped application/container/dashboard metadata to `0.10.0-SNAPSHOT` / `0.10.0`. Existing V1-V5 Flyway migrations and application features are unchanged.

## Security and repository checks

- ALB ingress is empty by default and accepts only explicitly supplied CIDRs; database, Kafka, worker, demos, and backend management paths remain private. Only `/api` is routed to the backend, while all other paths use the dashboard target group.
- RDS is private and encrypted, with AWS-managed master credentials referenced from ECS rather than stored in Terraform variables or Git. Only the backend task security group can connect to PostgreSQL.
- ECR tag mutability is `IMMUTABLE`; deployment tags are `sha-<40-character commit>`.
- ECS has separate execution/task roles per service, deployment circuit breakers, private networking, health checks, CloudWatch logs, and no public task IPs. Execution policies scope image pulls and log writes to each service's own ECR repository and log group; only the backend execution role can read the database secret.
- Backend and probe-worker task roles alone receive MSK data-plane permissions, and only their dedicated Kafka-client security groups can reach MSK. The task-role trust policies include source-account and ECS task ARN conditions.
- Endpoint-only task startup uses private ECR API, ECR Docker, CloudWatch Logs, and Secrets Manager interface endpoints plus an S3 gateway endpoint. Fargate does not require an ECS endpoint, and attached task-role credentials do not require STS. Public probes, external Kafka, and external OTLP still require NAT; a blocking precondition enforces that declaration.
- GitHub's role trust is restricted to the configured repository and protected environment. The workflow has `id-token: write` only in the deploy job and exposes no long-lived AWS key inputs.
- The secret/path/attribution scan found no AWS access keys, private keys, local user paths, or internal-tool attribution in the changed deployment sources/docs.
- `git diff --check` passed. Terraform state, `.terraform/`, plan files, `terraform.tfvars`, auto tfvars, and crash logs are ignored; the provider lock file is intentionally tracked.

## Cloud validation boundary

No AWS account or credentials were available or requested for this validation. Consequently:

- Terraform syntax, formatting, modules, provider schemas, and static lint are validated.
- Docker images and the complete local runtime path are validated.
- AWS quotas, permissions, regional availability, remote state, `terraform plan`, resource creation, service stabilization, OIDC assumption, ECR push, and live ALB/RDS/MSK behavior remain unvalidated until an operator follows `docs/aws-deployment.md` and explicitly approves a plan/apply.
- Current costs must be recalculated immediately before deployment. MSK Serverless, RDS, ALB, NAT/endpoints, Fargate, logs, images, and secrets all have independent charges; zero ECS tasks does not make the baseline free.

Nothing was committed, pushed, published to ECR, or deployed to AWS during V0.10 implementation.
